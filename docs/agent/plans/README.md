# 计划文档

给**维护者与 AI** 看的方案与计划：某项**跨仓改动**在本仓这一侧的落地内容。

**契约**型文档（现在是什么样、改的时候要注意什么）在上一级 [`../`](../)。跨仓改动的完整方案
（服务端侧的设计取舍、分阶段安排、验证结论）在 Suwayomi-next 的 `docs/agent/plans/` 里，本目录只放
本仓要做的事，每条都链回那份方案。

| 文件                          | 内容                                                                                                  |
| ----------------------------- | ----------------------------------------------------------------------------------------------------- |
| `backup-options-alignment.md` | 备份选项对齐 Mihon：本仓已有的分组/隐藏机制、10 个复选框与灰化依赖、`autoBackupInclude*` 设置名的同步 |
| `database-settings.md`        | 数据库设置接线：服务端设置页新增「数据库」分区、四个字段与两条只读信息、重跑 codegen                  |

## 维护约定

- 已定的选型**连日期一起留着**（「已定（YYYY-MM-DD）」），它是后来者判断「能不能改回去」的唯一依据。
- 落地之后**不删文档**：把结果补成一节（「落地情况」），否则下一个人会照着已失效的前提再推一遍。
- 与代码现状对不上的口径当场改掉 —— 计划里的过时事实比没有文档更糟。
